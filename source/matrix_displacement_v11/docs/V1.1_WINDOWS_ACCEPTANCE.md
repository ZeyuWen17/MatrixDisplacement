# V1.1 Windows GUI / 自动恢复 / 发布验收单

> 本清单由用户在实际 Windows 计算机上执行并填写；**初始所有步骤均未实机确认**。离屏测试通过 ≠ Windows 图形交互全部通过。

## A. 前置条件

- [ ] 确认 Windows 10/11 64 位、Python 3.10+、可用网络或完整离线依赖。
- [ ] 解压到普通可写目录，勿直接从 ZIP 内启动。
- [ ] 运行 `py -3 -m venv .venv`、`.\.venv\Scripts\python.exe -m pip install -r requirements-gui.txt`。
- [ ] 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\windows_acceptance.ps1` 并保存完整终端输出。
- [ ] 用 `.\.venv\Scripts\python.exe -m matrix_displacement.gui` 打开真实窗口。

## B. 自动保存

- [ ] 加载悬臂梁，拖动节点或添加节点，看到窗口标题 `*`（有修改未保存）。
- [ ] 等待 3–5 秒（防抖周期 2.5 秒），确认目录 `%LOCALAPPDATA%\MatrixDisplacement\recovery` 中出现新的 `session-<id>.json`。
- [ ] 再修改荷载并等待，确认快照更新，原模型 JSON 没有被覆盖。
- [ ] 手动保存 JSON 后，确认当前会话的恢复快照被清除；关闭时不再提示未保存。
- [ ] 修改后正常退出，分别测试“保存 / 不保存 / 取消”：保存与不保存清理当前快照，取消不关闭程序也不删除快照。
- [ ] 在模型未保存时模拟**强制结束进程**（避免用真实重要工程模型），然后重新启动程序，确认列出恢复候选项。
- [ ] 分别测试“恢复草稿 / 删除草稿 / 暂不处理”；恢复后标题出现 `*`，**不能静默覆盖原 JSON**。
- [ ] 同时留下两个不同会话快照，确认不会互相覆盖，且可通过“文件 → 恢复自动保存草稿...”选择。
- [ ] 模拟损坏的恢复 JSON，确认被安全跳过、没有无提示删除或崩溃。
- [ ] 手动保存恢复的模型后，再运行连续梁和桁架算例，确认原算法未受影响。

## C. GUI 交互 / DPI / 性能

- [ ] 鼠标单击、双击、框选（左右双向）、Ctrl/Shift 多选、组拖拽、撤销与重做。
- [ ] 节点/杆件参数修改、支座/节点荷载/杆件荷载添加与删除。
- [ ] 滚轮缩放、中键平移、全结构适配、不同分辨率及 125%/150% DPI。
- [ ] 教学 / 快速模式均可求解；四种图形显示、数据查询、CSV/PNG/报告导出。
- [ ] 不稳定结构、无效数值、只读路径、磁盘空间不足时得到明确错误，而不是静默产生数据丢失。
- [ ] 大模型（数百单元）、密集标注和复杂多选，观察渲染速度及内存占用。

## D. Windows EXE

- [ ] 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\build_exe_windows.ps1`。
- [ ] 确认产生 `outputs\dist\MatrixDisplacement\MatrixDisplacement.exe` 和 `BUILD_VALIDATION.txt`，离屏 `--self-test` PASS。
- [ ] **实际双击 EXE**，检查窗口、交互、数值分析和图形输出。
- [ ] 将整个 `outputs\dist\MatrixDisplacement\` 拷贝到**未安装 Python**的另一台受支持 Windows 电脑，重复基本运行测试。
- [ ] 测试普通用户权限、中文用户名路径、目录只读、Qt 插件加载、杀毒软件提示。
- [ ] 收集出错日志：`%LOCALAPPDATA%\MatrixDisplacement\logs\gui_errors.log`。
- [ ] 如果需要对外发行，另行处理安装器、数字签名和受信任的发布渠道。

## E. 已知限制和验收反馈

- 自动保存为**2.5 秒编辑防抖 + 每 60 秒周期兜底**，刚编辑后立即断电仍可能损失最后几秒；不是实时日志型保证。
- 快照仅备份当前结构模型，不备份全部撤销历史、窗口布局或计算结果。
- 自检仅覆盖 Qt 创建窗口、求解、绘图、恢复写入；真实人机交互仍需要上述人工步骤。
- 目前不支持跨设备同步、多用户协作冲突合并，以及自动识别已修改磁盘文件的复杂合并。
