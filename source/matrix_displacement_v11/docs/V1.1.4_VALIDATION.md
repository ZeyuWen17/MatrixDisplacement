# V1.1.4 恢复草稿清理异常处理

日期：2026-11-07。

## 本次改进

- 统一处理恢复草稿清理时的 OSError；失败保留文件，并在状态栏持续提示旧草稿可能已过时。
- 新建、加载算例及打开模型时，旧草稿删除失败不再打断新模型路径、历史、未保存状态和恢复会话的切换。
- 正常关闭时，若用户已确认保存或放弃，但旧草稿删除失败，显示提醒后正常关闭；取消关闭仍保留计时器和草稿。
- 撤销到已保存状态时，清理失败不再冒出未处理异常。
- 恢复草稿成功后，旧副本删除失败不再误报恢复失败；当前会话快照和旧副本均保留。
- 恢复对话框中删除草稿失败会提示，文件仍保留。
- 源码打包提前排除虚拟环境、构建目录和测试临时目录，避免遍历受限临时路径；验证日志仍随源码交付。

## 验证

完整回归 288 passed、1 skipped（仅非 Windows XDG 路径测试）。新增 8 个故障注入场景，覆盖新建、加载算例、打开模型、关闭、取消关闭、撤销、恢复及指定草稿清理失败。日志：reports/validation/pytest-v114-final.txt。

测试最初受沙箱临时目录权限限制；在获准的沙箱外重跑后通过。失败日志保留，不计入通过结果。

## 限制

不能强制删除受系统权限或其他程序占用保护的文件；下次启动仍可能出现旧草稿，应核对内容和时间。清理异常验证为自动化故障注入，本轮不新增真实鼠标验收结论。跨电脑、高 DPI、多显示器和完整崩溃恢复手动流程仍待验证；保存冲突检测不是文件锁，也不自动合并。

EXE 构建及打包后离屏自检通过；校验和与构建记录一致。证据：reports/validation/build-v114.txt、reports/validation/BUILD_VALIDATION_v114.txt。
